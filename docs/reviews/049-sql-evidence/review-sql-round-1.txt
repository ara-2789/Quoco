5. Findings
B-1. Approval attribution can be rewritten after the fact (proven on the stub)

What breaks

TR4c(4) (lines 662-669) locks the four content fields while a delivery is approved or cancelled. Nothing locks approved_by, approved_at, rejected_* or cancelled_*.
P1: On an approved row, UPDATE … SET approved_by = <other user>, approved_at = now() + 3 days with the status unchanged succeeded. The row then read status=approved approved_by=c2.
P2: I then ran path 1: unlink the self-link, which takes the snapshot, then cancel. The cancel UPDATE also rewrote approved_by. Result: the snapshot says c2 approved it, the delivery row says c1.

Why it matters

Round 2 rejected Option 1 so that “a wrong stamp is impossible”, and B2 removed caller input from the snapshot. But the snapshot copies its source, the delivery row, and that source can be rewritten.
D-23 says “approved means locked”. As written, that covers the content but not who approved it.
It is reachable the same way B2 was, through a bug in a PR-B definer function. Same grade.

Fix (in trg_deliveries_before_update, raising E11): each group may change only on its own status transition.

approved_by/approved_at: set NULL→value only on a move into approved. Cleared value→NULL only on cancelled → incomplete/awaiting_pm (restore).
rejected_*: set only on a move into rejected.
cancelled_*: set on a move into cancelled, cleared on restore.
Any other IS DISTINCT FROM raises E11.

Test (T-TRIG)

Rewrite the approver with the status unchanged → E11.
Cancel while changing approved_by → E11.
RED: the current file. GREEN: approve, cancel, restore and reject all still pass.
B-2. A self-link can be inserted onto a cancelled delivery (proven on the stub)

What breaks

TR2’s self-link branch (line 493) refuses only rejected.
P3: With A1 cancelled and no PM links on the invoice, inserting a new self-link before restoring A1 succeeded. Result: A1 status=cancelled, active links on A1=1.

Why it matters

TR4c(3) refuses moving to cancelled while a link is active. Inserting a link onto a cancelled delivery is the other direction, and it’s open.
Paths 2 and 4 rely on a header comment (“never the self-link first”) to stay correct.

Fix

Line 493: ELSIF v_status IN ('rejected', 'cancelled') THEN … E5.
No legitimate path is affected: paths 2 and 4 restore the delivery before inserting the self-link, and creating an invoice inserts its delivery as incomplete.
This turns the header comment into a rule the trigger enforces.
