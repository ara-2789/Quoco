### BUILD NOTES, ROUND 2 (deviations and flags, 2 Nov 2026)
1. DEVIATION FROM THE KEY SPEC (caught by the test-db-free T-OTP-07 restatement, T-UX-6, first run, 1 failed / 54 passed): the spec'd key `${step}|${error}|${email}` rendered the RAW ?error= value into the form's data-latch-key attribute, so `?error=NOT_A_REAL_KEY` reached the HTML. That is exactly what T-OTP-07 forbids (it asserts the raw key is never rendered), so the real T-OTP-07 would have failed in CI. Fix: the page passes loginFormKey only values it already trusts: step only when 'code'; error only if it is a key of ERROR_MESSAGES, otherwise 'GENERIC' (the same collapse errorMessageFor does); email only on the code step, where isValidEmail runs before anything renders. The key still differs for (email step, no error) = "||", (email step, RESEND_RATE_LIMITED) = "|RESEND_RATE_LIMITED|", (code step, WRONG_CODE) = "code|WRONG_CODE|<email>". Pinned by a new T-UX-8 row (unknown error + hostile email on the email step render key "|GENERIC|", raw text absent from the HTML); control C6 turns T-UX-8 red.
