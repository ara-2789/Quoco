### EMAIL-KEEP NOTES
1. NOT unit-testable in this repo (node env, no jsdom): the EmailInput mount effect (reads sessionStorage into the empty field) and the save inside onSubmit (reads the field, writes sessionStorage). The pure helpers (T-UX-11) and the server HTML (T-UX-12: same attributes, empty value) are tested; the browser behaviour is a MANUAL check: with a rate-limited Send code, the field must come back filled, and "Already have a code? Enter it here" must navigate without the "Please fill in this field." message.
2. The smoke gate is signed-out/server-side only: it proves /login still renders (the crash class of ba3dd3d), not the restore itself.
3. test/login-otp.test.ts NOT run (test-db held by the backend). Unchanged in this commit.
4. Privacy: the address lives in sessionStorage (tab-scoped, cleared when the tab closes), key quoco.login.email, written only from the email form's submit. It is never put in the URL, a cookie, a request other than the form's own, or any message. On a shared computer it persists until the tab closes; a different PM signing in on the same tab after a failed attempt would see the previous address pre-filled in the email field.
5. Edge: the restore skips a field the browser already autofilled (non-empty on mount). The have-code GET button, like Send code, saves before navigating (its submit event fires), so a have-code click also remembers the address.
6. The log copy committed as docs/reviews/login-otp-ux-email-keep-log.txt is a byte copy of this file as of the commit (it cannot contain its own commit SHA; the pushed head SHA is in the report).
