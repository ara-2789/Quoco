**R3: the lock order is right in shape and incomplete in contract. Not cleared.**
- Deadlocks abort with 40P01 and do not corrupt data, so the real defect is the isolation finding **B3**. Required changes:
  - **Name the mode at each level.** Every link or unlink path takes level 2 on a **DC** delivery `FOR SHARE`, never stronger.
    - Mechanism: txn A (unlink Dd from I1) holds I1 and wants Dd. Txn B (link Dd to I2) holds I2 and `FOR SHARE` on Dd, and waits on A at the A33 unique index.
    - If A's Dd lock is stronger than SHARE, that is a cycle. Retype and reject are the only exclusive takers, and they take no other lock.
  - **TR1: use `FOR NO KEY UPDATE`, not `FOR UPDATE`.** `FOR UPDATE` also blocks `FOR KEY SHARE`, so it stalls every FK check that references the invoice document. TR5 makes the key columns immutable anyway.
  - **TR3 must not lock the delivery itself.** It runs at level 3, so a lock there inverts the order.
    - Make the contract self-enforcing instead. TR4 on a row with `created_from_invoice_id IS NOT NULL` does `PERFORM … FROM public.capture_documents WHERE id = NEW.created_from_invoice_id FOR NO KEY UPDATE`.
    - A correct caller already holds that lock, so the call is a no-op. An out-of-order caller gets 40P01 instead of a silent race.
    - Credit: the unlocked read of `created_from_invoice_id` to find the invoice is safe only because TR4a makes it immutable. Say so in the file.
  - Write the sequence for each PR-B path (link, unlink-with-restore, reject automatic, reject DC, approve, retype) as numbered lock steps in the SQL package.

## 3. Findings beyond R1–R8

**B1. A rejection can leave an active link on a rejected delivery (proven).**
- TR2 refuses linking *to* a rejected delivery only at link INSERT. Nothing refuses rejecting an *already-linked* DC delivery. D-3 covers automatic deliveries only.
- Stub T9: `UPDATE deliveries SET status='rejected'` on a PM-linked DC gives `UPDATE 1`. The end state is `rejected | pm_manual | link_active t`. The invoice's expectation is then satisfied by goods the PM rejected.
- Fix: TR4c refuses `→ rejected` while any active link exists, for both DC and automatic deliveries.
  - The reject function first locks the invoice, then locks the delivery `FOR NO KEY UPDATE`, then unlinks (`'delivery_rejected'`), then updates the status.
  - This is the same both-directions shape you already built for internal transfers (TR2 and TR4b).
- Test: link, then reject, expects the E6-class refusal. Unlink, then reject, succeeds.

**B2. The GAP A snapshot is forgeable at INSERT (proven).**
- Stub T7: a link row inserted already unlinked, with a caller-supplied `superseded_approval_by` and `superseded_approval_at`, gives `INSERT 0 1`.
- D-2 was chosen because the trigger copies the stamp, so a wrong stamp is impossible. As planned, that holds only on UPDATE.
- Fix in TR1:
  - Refuse INSERT when any of `unlinked_*`, `unlink_reason` or `superseded_*` is non-NULL.
  - TR3 **overwrites** `superseded_*` (and `superseded_from_status`) unconditionally from the delivery. It never trusts NEW.
- Test: a forged insert gets refused. An update carrying a caller-supplied snapshot gets overwritten.

**B3. TR1, TR2 and TR4b hold only under READ COMMITTED (proven).**
- I raced a link INSERT against a retype to `internal_transfer`, with A committing after B had taken its snapshot.
  - With B in READ COMMITTED: `ERROR: E6`, end state `type=supplier, active_links=1`. Correct.
  - With B in REPEATABLE READ: no error, end state **`type=internal_transfer, active_links=1`**.
- Mechanism: the BEFORE-row trigger does wait for the tuple lock. But under RR its EXISTS query reads the transaction snapshot, which predates the link's commit. The link only locked the row and did not update it, so no serialization failure fires.
- TR1's XOR check (lock the document, then read the links) has the same shape.
- Fix: the first line of every invariant trigger is `IF current_setting('transaction_isolation') <> 'read committed' THEN RAISE …`. That turns a silent write-skew into a loud refusal.
- Test: the same race in the rehearsal on PG17, both isolation levels. The RR case must show the refusal.

**S1. `received_at DEFAULT now()` records processing time, not receipt time.**

- Fix: no DEFAULT. NOT NULL, supplied by the RPC from the inbound record. If the inbound path is synchronous and you want the default anyway, state it and pin where receipt time is captured.

**S2. The idempotency key sits on the leaf.**
