**S-B. The second orphan probe cannot detect the D-3 invariant.**
- Under A28, every invoice gets an automatic delivery that is never deleted. So `NOT EXISTS (deliveries …)` is false for every invoice that went through the RPC, and the `AND NOT EXISTS (active link)` branch never runs.
- The probe finds invoices with no automatic delivery. It cannot find "an invoice with no active link whose automatic delivery is not rejected".
- Add that as a third probe:
  `kind='invoice' AND NOT EXISTS (active link) AND NOT EXISTS (deliveries x WHERE x.created_from_invoice_id = d.id AND x.status = 'rejected')`.
- It must return 0 after every scenario, including reject-DC-with-restore.

**S-C. Path 4's level-1 key is mutable.**
- Paths 2 and 3 find I through immutable columns (TR3, TR4a). Path 4 finds I through "Dd's active link", which another transaction can change between the unlocked read and the Dd lock.
- Postgres cannot release a row lock inside a transaction. So on a mismatch at re-read, the only in-order response is to raise E11 ("This delivery has changed. Refresh") and stop. Never take I after Dd.
- TR4's self-enforcing lock covers automatic deliveries only, so nothing catches this inversion for a DC.
- Test (CI-only): reject Dd while a concurrent link of Dd commits. Expect E11 or E5, never 40P01.

**S-D. On test-db, the DOWN guard trips on Option Y's own helpers.**
- The `quoco_test_capture_*` bodies name the four tables, so the intensional guard matches them and aborts the test-db DOWN rehearsal.

- (N) Restrict the guard to non-system namespaces.

**S-F. Capture-loss window (pre-existing; relocated to PR-B, where it is blocking).**
